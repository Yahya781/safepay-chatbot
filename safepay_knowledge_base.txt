## Safepay API Documentation

### API Overview
Safepay is a regulated payments service provider that enables developers to orchestrate money movement between customers and businesses with ease and speed. The Safepay API makes it simple for businesses and financial platforms to create payment sessions, manage subscriptions, issue invoices, and exchange value by sending and receiving money.

The Safepay API is based on REST principles, returns JSON responses, and uses standard HTTP response codes.

### Environments
Safepay offers two environments to developers: production and sandbox.
- Sandbox: Any transaction performed in the sandbox environment has no financial impact. Safepay provides test credentials for payment instruments that can be used while integrating.
- Production: Used for live transactions after completing onboarding.
- To begin integrating, sign up for a free sandbox account to get access to all of Safepay's APIs. After completing integration, contact the Safepay team to create a production account and complete onboarding.

### API Authentication
Safepay supports authentication through JWT tokens as well as API secret keys. Most APIs support both JWT and Secret Key based authentication, but where an API supports a specific type of authentication, it will be mentioned in the documentation.

- JWT Token: Set the Authorization header to "Bearer" followed by the JWT token.
- Merchant Secret Key: Set a header called "X-SFPY-MERCHANT-SECRET" and use the merchant Secret Key as the value. The Secret Key can be found in the Developer section on the merchant dashboard.
- Time-based Token: For client-to-server requests, a time-based token may first be generated server-side using the Secret Key. This is passed similarly to the JWT token by setting the Authorization header to "Bearer" followed by the time-based token.

### Login Company Endpoint
POST /v1/company/login — Authenticates a company/admin user and returns a token.
Request body requires email and password fields. The response returns a token (client token), name, email, api_key, and other company details.

### Create Merchant JWT Endpoint
POST /auth/v1/company/authenticate — Generates a JWT session token for a merchant.
Request body requires client, email, and password fields. The email and password are those of the Admin user who created the account. The JWT token can be extracted from the "data" object at the "session" property. Each session token is valid for a 24 hour period.
